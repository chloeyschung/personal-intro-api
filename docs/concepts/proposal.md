# 컨셉 3안 제안 (2026-09-16)

코딩 전에 컨셉 3개 제안드립니다. 세 개가 서로 다른 건 스타일이 아니라 **구조를 조직하는 은유**입니다 — 색인 / 필름 / 도면. 따라서 레이아웃, 내비게이션 모델, 인터랙션이 전부 달라집니다.

---

# 01 — INDEX (색인)

**Core idea**
사이트 전체가 책 뒤에 붙은 색인. 색인은 설명하지 않고 **가리키기만 한다**. 항목들이 서로를 참조(see also)하고, 그 연결선이 초상화가 된다. 브리프의 "Don't explain me, let people infer me"를 가장 문자 그대로 구현한 형식.

**Homepage composition**
첫 화면은 판권면(colophon) 한 덩어리 — 이름, 연도, 항목 수 — 그리고 곧장 색인이 시작된다. 카테고리별 섹션이 아니라 **한 줄 항목이 쌓인 단일 리스트**. 영화·작곡가·도시·향이 같은 리스트에 섞여 있다. 분류가 아니라 병치.

```
A 001   ARRIVAL                          FILM     2016
A 002   ACQUA DI PARMA / Fico di Amalfi  SCENT
B 003   BACH                             MUSIC
B 004   BERLIN                           PLACE    52.52 / 13.40
```

**Navigation**
상단 필터 한 줄 (ALL / FILM / MUSIC / PLACE / SCENT / WORK / NOTE). 선택하면 나머지가 사라지지 않고 **흐려진다** — 색인의 연속성을 깨지 않기 위해. 페이지 이동 없는 단일 페이지.

**Typography**
제목은 큰 세리프(EB Garamond / Source Serif — 책 본문의 질감), metadata는 아주 작은 모노 대문자. 좁은 단, 넓은 행간, 큰 여백.

**Visual references**
책 색인 · 경매 카탈로그 lot list · 미술관 소장품 DB · Fondazione Prada 출판물

**Signature interaction — see also**
항목에 hover하면 오른쪽 여백에 짧은 메모 한 줄. 클릭하면 **연결된 항목만 남고 나머지가 흐려진다.** Arrival → Incendies, Sicario, Debussy, Kobe. 연결 이유는 어디에도 쓰지 않는다. 방문자가 연결을 보고 추론한다.

**Content**
전부 사용 가능 (38개 항목). 색인은 많을수록 설득력이 생긴다.

**첫인상**
"정리는 철저한데 자기 얘기는 한 줄도 안 했네." 조용하고 지적. 연결을 더 눌러보려고 다시 오게 됨.

# 02 — SUBTITLE (자막)

**Core idea**
사이트가 한 편의 영화. 방문자는 읽는 게 아니라 **본다**. 모든 콘텐츠는 검은 화면 하단의 자막으로만 등장하고, 스크롤은 필름을 감는 행위다.

**Homepage composition**
완전한 검은 화면. 좌상단에 타임코드 `00:00:14:08`, 우상단에 `REEL 01 / 06`. 화면 중앙은 비어 있다 — 여백이 콘텐츠. 하단 자막이 페이드로 들어왔다 나간다.

```
                      [이름]

             A collection of things
          watched, heard, visited, noticed.
```

각 REEL이 카테고리 — 01 FILMS / 02 MUSIC / 03 PLACES / 04 SCENT / 05 WORK / 06 NOTES.

**Navigation**
메뉴 없음. 하단에 얇은 **스크러버** 한 줄, 6개 챕터 마커. 드래그로 구간 이동, 키보드 ←/→로 씬 단위 이동.

**Typography**
자막용 산세리프(Inter / Helvetica Now), 타임코드는 모노 10px. 자막은 항상 하단 고정 — 영화 자막 규칙 그대로. 순백 금지, 낮은 대비의 회색.

**Visual references**
Villeneuve 오프닝 크레딧 · Criterion 챕터 메뉴 · Lost in Translation의 자막 장면 · 필름 리더 카운트다운

**Signature interaction — freeze frame**
자막 위에 커서를 올리면 검은 화면에 아주 느리게 한 장이 떠오른다 — 영화면 포스터에서 추출한 색면, 도시면 흐린 사진, 향이면 색. 커서를 떼면 다시 검게. **기본적으로 아무것도 보여주지 않고, 찾을 때만 보여준다.**

**Content**
영화·음악·도시 중심. 향은 색면으로, work는 마지막 REEL에 엔드크레딧 3줄로. 관심사는 오프닝 카운트다운에 흐르는 텍스트.

**첫인상**
"뭘 보여주려고 안달하지 않는구나." 서늘하고 통제되어 있음. 셋 중 가장 오래 기억에 남을 가능성.

# 03 — PLAN (도면)

**Core idea**
사이트가 한 장의 건축 도면. 콘텐츠는 문서가 아니라 **평면 위에 놓인 것들**이고, 방문자는 도면 위를 이동하며 확대한다. 줌 레벨에 따라 정보량이 달라진다.

**Homepage composition**
흰 바탕, 0.5px 해어라인으로 그려진 평면도 한 장이 화면 전체. 방 여섯 개(WORK / FILMS / MUSIC / PLACES / SCENT / NOTES)의 **면적이 서로 다르다 — 관심의 크기가 곧 면적.** WORK가 가장 작다. 우하단 타이틀 블록에 이름, 연도, 축척 `1:100`, 도면번호 `INDEX-2026`.

**Navigation**
방을 클릭하면 카메라가 이동+확대. 스크롤=줌, 드래그=팬, 뒤로가기=줌아웃. 상단에 현재 좌표와 줌 레벨.

**Typography**
제도 라벨 스타일 — 작은 대문자에 넓은 자간(0.15em), 치수선 숫자는 모노. 큰 타이포는 오직 타이틀 블록에만. 화면 대부분이 선과 여백.

**Visual references**
SANAA 평면도 · OMA 다이어그램 · 住宅特集 도면집 · 미술관 층별 안내도

**Signature interaction — 줌 레벨별 정보 밀도(LOD)**
멀리서는 방 이름만 보인다. 확대하면 방 안의 항목이 나타나고, 더 확대하면 치수선처럼 주석이 붙는다 — `ARRIVAL ——— 2016 · 116min`. **확대하지 않으면 아무 정보도 주지 않는다. 관심을 가진 만큼만 보인다.**

**Content**
면적으로 위계를 표현. PLACES는 실제 지리에 맞춰 도시를 좌표 배치, SCENT는 색면 타일, WORK는 가장 작은 방.

**첫인상**
"취향이 아니라 사고 방식을 보여주는 사람." 정밀하고 차갑고 지적. 건축·도시 관심사와 사이트의 형식이 일치해서 그 부분은 따로 설명할 필요가 없어짐.

**추천: 01 INDEX.** 브리프의 핵심 원칙에 형식 자체가 가장 정확히 대응하고(색인은 원래 설명하지 않는 문서다), cross-reference 인터랙션이 "연결로 사람을 추론하게 한다"는 목표를 직접 수행합니다. 다만 **가장 기억에 남는 건 02**이고, **취향과 형식이 가장 일치하는 건 03**입니다. 02의 freeze-frame 방식을 01의 hover 동작으로 빌려오는 조합도 가능합니다.

어느 쪽으로 갈지 정해주시면 그때 `frontend/public/intro.html`을 그 컨셉으로 다시 만들겠습니다 (과제 요건상 메모장 페이지와 상호 링크는 유지).

# 추천 방향 및 페이지 구조

**01 INDEX를 뼈대로, 각 페이지마다 다른 인터랙션을 붙이는 방향**을 추천합니다.

이유는 페이지 단위로 만들고 싶다는 조건 때문이에요. 02와 03은 **하나의 연속된 화면**이 곧 컨셉입니다 — 02는 끊기지 않는 한 편의 필름이라 페이지로 자르면 컨셉이 깨지고, 03은 도면 한 장이 전부라 방을 페이지로 분리하면 "한 장의 도면"이라는 전제가 사라집니다. 반면 색인은 원래 **뒤에 본문이 있는 문서**예요. 색인이 홈이 되고 항목이 각자의 페이지로 열리는 게 형식적으로 자연스럽습니다.

그리고 이 구조에서 02·03의 좋은 부분을 **개별 페이지의 인터랙션으로 흡수**할 수 있습니다.

## 제안 구조

```
/intro.html     INDEX      색인 — 종이, 세리프. 항목 hover→메모, click→연결된 항목만 남음
                           카테고리를 누르면 해당 페이지로 진입

/films.html     FILMS      02의 방식. 검은 화면, 제목만. 커서를 올리는 동안만
                           그 영화의 색이 떠오름. 스크롤=타임코드

/places.html    PLACES     03의 방식. 좌표 평면 위 9개 도시. 확대할수록
                           좌표→메모 순으로 정보가 늘어남

/music.html     LISTENING  현재 듣는 곡 한 줄이 크게, 나머지는 작은 로그.
                           hover하면 작품명이 교체되는 정도의 조용한 움직임

/scent.html     SCENT      향수병 없이 색면만. 색 위에 커서를 올리면
                           단어 세 개(airy / citrus / warm)가 나타남

/work.html      WORK       가장 작고 가장 조용한 페이지. 세 줄.

/index.html     LAB        과제 요건인 메모장 API 데모 — 색인의 한 항목으로 편입
```

마지막 줄이 포인트입니다. 과제에서 요구하는 프론트·백엔드 연동 페이지를 "과제라서 붙인 페이지"로 두지 않고, **색인 안의 한 항목(LAB — 지금 만들고 있는 것)**으로 넣으면 링크 요건도 자연스럽게 충족되고 사이트 컨셉도 안 깨집니다.

## 묶어주는 장치

페이지마다 분위기가 달라지되 따로 놀지 않으려면 세 가지를 고정합니다 — 같은 타입 시스템(Newsreader + IBM Plex Mono), 모든 페이지 좌상단의 동일한 위치에 있는 `← INDEX`, 그리고 모든 페이지 우상단의 항목 번호(`A 003 / 35`). 색인에서 왔다는 감각이 계속 유지됩니다.

**트레이드오프**: 페이지가 7개라 01 단독보다 작업량이 3~4배입니다. 마감이 9/22이니 순서를 정해두면 좋겠어요 — INDEX + FILMS + LAB 세 개만 있어도 과제 요건은 완전히 충족되고, PLACES·SCENT·MUSIC·WORK는 그 다음에 하나씩 붙이면 됩니다.

이대로 갈까요? 그러면 INDEX부터 제대로 만들어서 `frontend/public/`에 넣고, 한 페이지씩 쌓아가겠습니다.
